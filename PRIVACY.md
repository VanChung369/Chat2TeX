# Chat2TeX Privacy Notice

Chat2TeX processes conversation text, images, LaTeX source, compiler logs,
PDFs, and ZIP files locally inside the Chrome extension. It does not upload
conversation content or generated output to a compilation server, and it
adds no analytics.

On the first PDF export, the extension downloads six pinned compiler files
from a Chat2TeX release hosted by GitHub. GitHub and its release asset
delivery service can observe normal request metadata, including the IP
address, user agent, and requested compiler filenames.

When a document requires a TeX Live file that is not already cached, the
extension requests a URL from `texlive2026.texlyre.org` containing only an
allowed numeric TeX format and a static filename. That server can observe the
IP address, user agent, numeric format, and requested filename. The request
does not include conversation text, source, cookies, authorization headers,
images, PDFs, or ZIP bytes.

Verified compiler and package files are cached locally so previously cached
documents can compile offline. Cache metadata includes file sizes, integrity
hashes, last-used timestamps, and negative lookups. Choosing **Clear cache**
removes compiler/package bytes, negative lookups, and the first-seen package
hash ledger. A later PDF export must download the required files again.

Temporary job source, image bytes, PDF bytes, ZIP bytes, and compiler logs are
kept only in offscreen memory and are released after download, cancellation,
a new job, or the fallback retention timeout. A sanitized job status may be
stored in Chrome session storage so the popup can reconnect. The offscreen
document accesses that storage only through a sender-validated message to the
background service worker; no conversation source or generated bytes pass
through that storage bridge.

Chat2TeX may request optional access to HTTPS image origins selected by the
conversation. Those requests are used only to fetch images for the local
export.
